# 校园失物招领信息管理系统

> 信息系统项目管理实训项目 · 项目代号 **V50-CAMPUS-LF-11**
> 团队：周四V50（24计算机一班 / 第 11 组）

## 一、项目简介

校园失物招领信息目前分散在班级群、表白墙和私聊中：检索困难、过期信息多、认领状态无法跟踪。
本项目把它们集中到一个系统中，让**学生**可以发布与查询失物/招领信息，让**辅导员或保卫处管理员**可以审核与下架信息。

## 二、功能范围

### v1.0（第一个版本）

| 需求编号 | 需求 | 状态 |
|---|---|---|
| #1 | 登录与角色权限（学生 / 管理员） | 已完成 |
| #2 | 失物与招领信息发布 | 已完成 |
| #3 | 列表展示与关键词/分类检索 | 已完成 |
| #4 | 信息详情查看 | 已完成 |
| #5 | 我的发布（含状态切换与删除） | 已完成 |

### v2.0（第二个版本，规划）

| 需求编号 | 需求 |
|---|---|
| #6 | 留言 / 联系方式 |
| #7 | 认领状态更新 |
| #8 | 管理员审核与下架 |
| #9 | 简单统计 |
| #10 | 缺陷修复与页面优化 |

**明确不做**：在线支付、即时聊天、物流、推荐算法、跨校信息、复杂实名认证、闲置交易。

## 三、技术栈

| 层次 | 选型 |
|---|---|
| 语言 | Python 3.12 |
| Web 框架 | Flask 3.1 |
| ORM | Flask-SQLAlchemy 3.1（SQLAlchemy 2.1） |
| 认证 | Flask-Login 0.6 |
| 数据库 | SQLite（开发/演示） |
| 前端 | Bootstrap 5.3 + Bootstrap Icons |
| 模板 | Jinja2 |
| 测试 | pytest 9.2 |
| CI | GitHub Actions |

选型理由：两人三周内要交付两个可运行版本，Flask 轻量、SQLite 零配置、GitHub Actions 对 Python 支持最直接，能把时间放在“过程记录”而不是环境搭建上。

## 五、本地运行

```bash
# 1. 创建虚拟环境
python -m venv .venv
.venv\Scripts\activate          # Windows
# source .venv/bin/activate      # macOS / Linux

# 2. 安装依赖
pip install -r requirements.txt

# 3. 初始化数据库与演示数据
python seed.py

# 4. 启动
python run.py
```

浏览器访问 <http://127.0.0.1:5000>

## 七、分支规范

| 分支 | 用途 |
|---|---|
| `main` | 主干，只接收已通过测试的代码，每个版本在此打标签 |
| `dev` | 日常集成分支 |
| `feature/<需求号>-<简述>` | 单个需求开发，例如 `feature/1-login` |
| `fix/<缺陷号>-<简述>` | 缺陷修复，例如 `fix/BUG-002-search` |

提交信息规范：`<类型>: <描述> #<禅道需求号或缺陷号>`
例如：`feat: 实现登录与角色权限 #1`
